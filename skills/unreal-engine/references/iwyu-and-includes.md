# IWYU and Include Hygiene

UE 5.x uses **Include What You Use** as the default policy. Each header must include exactly the headers for the types it names directly. Transitive includes are not guaranteed; the engine may break them at any minor version.

## The rules

1. **Forward-declare in headers** when the full type isn't needed (pointer/reference fields, function parameters).
2. **`#include` in the `.cpp`** when the type is actually used (member access, sizeof, instantiation).
3. **`*.generated.h` is the last include** in any header containing a `UCLASS`/`USTRUCT`/`UENUM`/`UINTERFACE`. UHT depends on this ordering.
4. **Never include `Engine.h`, `EngineMinimal.h`, `CoreUObject.h`, or `UnrealEd.h`** — they pull half the engine. The PCH already covers what's needed.
5. **No `using namespace`** at file scope. UE namespaces are minimal but the rule keeps headers safe.

## Header template

```cpp
// MyComponent.h
#pragma once

#include "CoreMinimal.h"
#include "Components/ActorComponent.h"
#include "MyComponent.generated.h"   // ALWAYS LAST

class USomeAsset;   // forward declaration

UCLASS()
class MYMODULE_API UMyComponent : public UActorComponent
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere)
    TObjectPtr<USomeAsset> Asset;
};
```

## CPP template

```cpp
// MyComponent.cpp
#include "MyComponent.h"

#include "Engine/World.h"
#include "SomeAsset.h"     // full definition now needed
```

## Module API macro

Public types in a module must use the `<MODULENAME>_API` macro on the class:

```cpp
class MYMODULE_API UMyComponent : public UActorComponent { ... };
```

Without it, linking from another module fails with unresolved externals. The macro is generated by UBT; it expands to `__declspec(dllexport)` on the owning side and `__declspec(dllimport)` elsewhere.

## PCH

UE generates a per-module PCH from `<Module>.Build.cs`. Don't manually include things just because they're in the PCH — IWYU still requires explicit includes for portability across configurations.

If `Build.cs` sets `PCHUsage = PCHUsageMode.UseExplicitOrSharedPCHs;` (the default), your headers are validated for IWYU correctness on every build.

## CoreMinimal.h vs CoreUObject.h

- `CoreMinimal.h` — bare essentials (containers, strings, math, log macros). Use in 99% of headers.
- `CoreUObject.h` — full UObject reflection surface. Avoid in headers; include the specific UObject header you need.

## *.generated.h failures

If you see `error C2143: syntax error: missing ';' before '*'` in a `UCLASS`, the most likely cause is:

1. `*.generated.h` is not last in the include list, OR
2. You added a `UPROPERTY`/`UFUNCTION` to a class that lacks `GENERATED_BODY()`, OR
3. You renamed a class but didn't regenerate the project files (delete `Intermediate/` and re-run "Generate Project Files").

## Forward-declaring templates

You cannot forward-declare a template instantiation directly. For `TArray<UMyType>` in a header, forward-declare `UMyType` and `#include "Containers/Array.h"` (already in `CoreMinimal.h`).

## Common include mistakes

- `#include "Engine.h"` → kills compile times. Replace with the specific subsystem header.
- `*.generated.h` not last → UHT errors on the next clean build.
- Including a header just for a `class Foo;` reference → use forward declaration instead.
- Cross-module includes without the module being in `Build.cs` → unresolved external linker errors. Fix the `Build.cs`, not the includes.
